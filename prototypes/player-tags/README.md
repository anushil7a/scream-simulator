# Local player-tag exploration (NOT production)

These are disposable Studio fixtures, not a shipped player-nameplate implementation. The art is an original navy/gold **name-only** prototype on a labelled, script-stripped clone of the local avatar. It is not another Player.

## Build and run

Use the project's existing trusted Luau and Rojo installations, available on PATH. From the repository root:

```text
luau-compile prototypes/player-tags/player-tag-baseline.client.luau
luau-compile prototypes/player-tags/player-tag-art.client.luau
python prototypes/player-tags/run_player_tag_smoke.py
python prototypes/player-tags/run_player_tag_art_smoke.py
rojo build prototypes/player-tags/player-tag-baseline.project.json -o build/PlayerTagBaseline.rbxl
rojo build prototypes/player-tags/player-tag-art.project.json -o build/PlayerTagArt.rbxl
```

The two projects use relative paths and contain only a Review LocalScript and Floor. There are no game/server scripts or storage calls. Generated smoke scripts and binary places go under ignored `build/`, not this directory. Both sources reject execution unless Studio and PlaceId/GameId are zero. **Do not publish these places or run them in a saved cloud place.**

Open the desired local file and start Play. The art fixture initially shows native baseline case 1. In the client context, access:

```lua
local review = game.Players.LocalPlayer.PlayerGui.PlayerTagReviewControl
review:Invoke("Cases")
review:Invoke("Case", 1)
review:Invoke("Snapshot")
review:Invoke("Prototype", 1) -- art fixture only, indices 1..6
review:Invoke("Stop")
```

Stop Play after use, errors or uncertain cleanup. A 15-minute watchdog attempts independent owned-object, viewer-property, root and camera cleanup. Restoration is best-effort and conditional; it is not a universal lifecycle guarantee.

## Native baseline

The actual local viewer and cloned subject properties are recorded before fixture mutation. The authored label becomes `HUMANOID FIXTURE`; native engine name/health overlays remain enabled according to the selected baseline case. The clone has its scripts stripped before parenting.

Cases 1–14: untouched damaged; Viewer near20/name-only30/far55 with name50/health25 ranges; Subject near30/name-only60/far85 with name80/health40 ranges; None near20; opaque/.99/.995 walls with viewer OccludeAll; opaque wall with viewer NoOcclusion; identical wall under a Humanoid-containing Model; and camera-only offset. The subject occlusion property is held fixed in the paired cases. Viewer and subject values, root and camera distances are recorded separately.

Optional third-argument overrides: `distance`, `nameRange`, `healthRange` (finite 0–150); `healthFraction` (0–1); `healthDisplay` (`AlwaysOn`, `AlwaysOff`, `DisplayWhenDamaged`). Each case recreates the subject, including after death. This is a representative fixture, not exhaustive boundary coverage. Snapshots prove configured state, **not drawn visibility**; settled screenshots are needed.

## Optional original art

Only in the art fixture, `Prototype` indices 1–6 select normal name, long name, Unicode name, opaque wall, .99 wall and .995 wall. The billboard is passive, RichText=false, bounded150–300×34 pixels, MaxDistance80, AlwaysOnTop=false and attached relative to head extents. Actual native text bounds and TextFits are reported, not assumed from mocks.

**Only the owned clone's native name AND health bar are suppressed. The prototype supplies a name, not health information. It is not health-equivalent or a production replacement.** It does not suppress any real Player's native display. It adds no level/status/health manager. Art mode restores the viewer's captured display defaults. Names are fixed synthetic fixture strings, not arbitrary user input.

## Evidence and limits

- Baseline whole-fixture mocked smoke:16 checks; two negative controls, including valid-syntax removal of the post-settle Stop fence failing its intended runtime assertion.
- Art whole-fixture mocked smoke:41 checks, covering six modes and return to baseline. Mock TextFits/metrics are not native font evidence.
- Coordinator reported native startup and15 observations (five baseline, six art, four front-view captures), with TextFits true in all six art cases. Normal/long/Unicode front screenshots were readable. Those captures are separate checkpoint evidence, not generated by these scripts.
- Native baseline name/HP overlays remained blank even unobstructed in this local fixture. **This does not establish real-player behavior or engine semantic equivalence.**
- No genuine second Player, team/EnemyOcclusion/team-color, replication, self-name hiding, platform name assignment, real respawn, physical input, OS text-size, or multiplayer performance verification.
- No production integration or publication authorization is implied. Do not attach this fixture to a real game or remove production health displays on its evidence.

Sources consulted: vault `World-Space UI - BillboardGui and SurfaceGui`; official [character name/health display](https://create.roblox.com/docs/characters/name-health-display) and [Humanoid NameOcclusion](https://create.roblox.com/docs/reference/engine/classes/Humanoid#NameOcclusion). Viewer-versus-subject occlusion distinctions must be observed in the actual intended player context.
